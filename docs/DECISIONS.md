# 产品与工程决策

| 决策 | 原因 | 取舍 / 后续验证 |
|---|---|---|
| 保留现有项目并逐步扩展 | 真实流式 AI、草稿和精选案例已有价值 | 生成解析仍保留在原 lib，避免为目录形式迁移全部代码 |
| Demo-first，无登录前置 | 招聘者和首次用户可以几分钟内完成流程 | 本地数据不会自动跨设备同步 |
| Score 不预测 CTR | 没有真实投放数据；结构质量与业务效果不同 | 规则评分只给检查提示，保留独立人工事实核对 |
| 模型失败由用户选择 Demo | 防止将模板输出伪装成 AI 成功 | 明确错误、保留旧版本，允许重试与取消 |
| 每次编辑和恢复追加版本 | AI 协作需要可回溯、可比较的用户控制 | 历史占用浏览器空间，提供 JSON 备份；不静默裁剪 |
| 优先 TikTok / Meta | 能覆盖短视频、Feed 与 Stories 的核心差异 | 规则是创作假设，不代表平台保证；Meta 以 Instagram/Facebook 选择 |
| 东南亚拆分为具体国家 | 语言、货币与表达不能按一个地区简单概括 | 首批仅新加坡与印度尼西亚，其他国家待评测 |
| 有限本地化模板 + 真实接口 | 没有 Key 也能验证完整产品路径 | 跨语言 Demo 重建而非逐句翻译，清楚展示限制 |
| 不进行 live competitor scraping | 避免来源、授权与稳定性问题 | 原创教学数据和用户手动内容；结构启发不复制原文 |
| Repository 封装 localStorage | UI 不需要自行编排持久项目集合 | 当前接口同步；远程接入须增加异步边界，不宣称即插即用数据库 |
| 保留原 Anker 精选案例 | 既有人工案例的镜头与证据细节优于泛化模板 | 品牌非官方练习；不代表所有生成都有相同质量 |
| 不默认采集分析数据 | 尚无真实用户研究与分析服务配置 | 提供事件契约，数据采集需要单独连接和隐私设计 |
| 克制的系统字体与中性界面 | 广告资产和操作层级比装饰更重要 | 不依赖远程字体，弱网络下保持布局稳定 |

验证目标：用户能理解三个策略差异，能发现证据缺口，能保留并恢复自己的修改，能解释为何针对一个市场调整 CTA；最终以真实使用研究与受控投放验证，而不是用 demo 数字证明价值。

## 2026-10-05 核心闭环收口

- 把 Directions 从成品选项卡拆成生成前的策略选择：先理解三种叙事，再决定把资源投入哪一个方向。旧成品仍可直接编辑。
- Improve 限制接受目标相关字段；只有仍等于旧 Hook / CTA 的首尾文字才同步。模型重写其他字段不直接覆盖用户编辑。
- Before / After 默认可见；What Changed 根据实际字段差异生成，不声称必然提升质量。只改说明文本不产生新版本。
- Compare 以版本为单位，可纳入本地化副本。评分只展示绑定该内容快照的历史记录，不重新计算并冒充旧评分。
- 本地化新增未提供价格会退回模型修正一次；允许保留原币种或移除价格，并明确提醒。原始版本始终可对照。
- Useful Signals 是实际操作的本地元数据，统计按版本去重；不回填旧复制、导出或使用行为，不把自动生成当价值。
- 沿用原技术栈和测试，未增加大型依赖，也未接入遥测、账户、数据库、支付或投放。
